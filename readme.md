## 📝 How I Document Problems

For most problems, I try to keep a short note along with the solution:

```text
Problem
Approach
Why this approach works
Time Complexity
Space Complexity
```

For problems where I make mistakes or discover a better approach later, I'll add those observations as well.

The goal isn't just to have the code.
**The goal is to be able to understand it again when I come back months later.**

## 🎯 Why This Repository?

I'm preparing for software engineering roles and want to become better at solving unfamiliar problems rather than relying on memorized solutions.

Some problems take minutes.

Some take hours.

Some need to be revisited several times before the idea actually sticks.

I'm keeping all of them here because the difficult ones are often the ones that teach me the most.

---

## 🔄 My Approach

When solving a problem, I generally try to follow this process:

1. Understand the problem completely.
2. Think about a brute-force solution.
3. Look for patterns or constraints that can improve it.
4. Implement the solution.
5. Analyze time and space complexity.
6. Revisit the problem if I struggled with it.
7. Try to remember the idea rather than memorize the code.
